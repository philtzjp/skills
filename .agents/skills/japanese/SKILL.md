# japanese

## 原則

Please remove all mannered prose.

英語の形を日本語に当てはめない。意味と意図を取って、日本語として自然な言い回しに組み直す。

判断に迷ったら次を試す。

- その文を日本語の話者が日常や業務でそのまま言うか想像する。
- 英語の原文を頭の中で復元し、直訳になっていないか確かめる。
- 述語が欠けていれば補う。
- 同じ語尾が3回以上続くなら文を変える。

## 体言止め

本文、説明文、会話文で体言止め（名詞に句点）を使わない。述語を補う。

- 対応。 → 対応しました。／対応します。
- 修正。 → 修正しました。／修正が必要です。
- 確認。 → 確認してください。／確認済みです。
- デプロイ。 → デプロイしました。
- 未対応。 → 未対応です。／まだ対応していません。
- 要確認。 → 確認が必要です。
- 認証エラーの修正。 → 認証エラーを修正しました。
- 詳細はドキュメント参照。 → 詳細はドキュメントを参照してください。

使ってよいのは、見出し、ラベル、UI のステータス表示（対応中、未対応）、極めて短い箇条書きに限る。

## 文末と依頼

- 〜どうぞ。 → 〜ください。／〜をお願いします。
- ご確認どうぞ。 → ご確認ください。
- お試しどうぞ。 → お試しください。
- 〜まで。 → 〜までです。／〜予定です。
- リリースまで。 → リリース予定です。
- 対応まで。 → 対応中です。／対応予定です。
- 以上。 → 以上です。
- よろしく。 → よろしくお願いします。

「〜まで」は副詞句として使い、述語を補う。それだけで文を切らない。

## 技術スラングの直訳

- land（PR、変更） 寄せる、着地する → マージする、取り込む、反映する
- drop（機能、サポート） 落とす、ドロップする → 削除する、廃止する、提供を終了する
- knock down、take down 倒す → 修正する、解消する、取り除く
- ship、push out 出す、送り出す → リリースする、公開する
- roll out 転がす → 段階的に展開する、順次提供する
- spin up 回す → 起動する、プロビジョニングする
- wire up 配線する → 接続する、組み込む
- bake in 焼き込む → 標準装備にする、組み込む
- bubble up 浮上する → 表面化する、上位に伝わる
- nail down 釘付けにする → 確定する、詰める
- call out 呼び出す → 明示する、指摘する
- follow up フォローアップする → 追って連絡する、後日対応する
- circle back 円を描いて戻る → 改めて検討する、後ほど戻る
- unblock アンブロックする → ブロックを解除する、障害を取り除く
- green-light 青信号を出す → 承認する、着手を許可する

バグを倒す、課題を倒す → バグを修正する、課題を解消する。

## 冗長・硬い構文

- 〜することができます → 〜できます
- 〜する必要がある → 〜が必要です／〜してください
- 〜していきます（乱用） → 〜します／順次〜します
- 〜となります → 〜です
- 〜に関して → 〜について
- 〜の方 → 削る
- 〜を実施する（乱用） → 〜する／〜を行う
- 〜についてお知らせします → 〜をお知らせします
- 問題なく動作します → 正常に動作します
- ご不明点がございましたら → 不明点があれば（トーンに応じて調整）

「〜きる」は英語の finish 〜ing や 〜 out の直訳になりやすい。安易に使わない。

- 仕様を書ききる → 仕様を書き上げる／仕様の起草を完了する
- タスクをやりきる → タスクを完了する
- 一覧を読みきる → 一覧を最後まで確認する

## カタカナ語

カタカナ語自体は悪くない。日本語で十分伝わる場合に和語を優先する。

- インプリメンテーション → 実装
- デプロイメント → デプロイ、展開
- レファレンス → 参照、参考
- コンフィグレーション → 設定
- バリデーション → 検証、入力チェック

リファクタリング、デプロイのような定着語はそのまま使う。

## トーン

- ユーザーへの説明や報告 — です・ます調。簡潔だが述語のある文。
- コミットメッセージ — 常体でよい。動詞で締める。
- UI のラベルやボタン — 短くてよいが、動詞形か明確な名詞句にする。
- 技術ドキュメント — です・ます調。体言止めは見出しのみ。

敬体と常体を混在させない。意図的に混ぜる場合を除く。

## 例

作業報告。

```
バグの修正。テストの実行。問題なし。
→ バグを修正し、テストを実行しました。問題はありませんでした。
```

次の手順。

```
次は PR のマージまで。
→ 次は PR をマージします。
```

依頼。

```
ログの共有どうぞ。
→ ログを共有してください。
```

コミットメッセージ。

```
認証まわりの修正。
→ fix: 認証エラーのハンドリングを修正

不要な依存関係を落とす
→ chore: 未使用の依存関係を削除
```

PR 説明。

```
この PR では変更を寄せます。レビューどうぞ。
→ この PR で変更を取り込みます。レビューをお願いします。

既知の問題を倒す対応。
→ 既知の問題を解消しました。
```

UI 文言。

```
保存。
→ 保存する

エラー。再試行。
→ エラーが発生しました。再試行してください。
```

長い文の分割。

```
今回の変更では認証フローを更新し、トークンの検証ロジックを修正し、
エラーハンドリングを改善し、テストを追加することができます。
→ 今回の変更では、認証フローを更新し、トークン検証とエラーハンドリングを
  修正しました。あわせてテストを追加しています。
```

## 出力前に確認する

- 本文に体言止めが残っていないか。
- 「〜どうぞ」「〜まで。」で文が終わっていないか。
- 寄せる、落とす、倒すが英語スラングの直訳になっていないか。
- 「〜きる」が不自然でないか。
- 一文が長すぎないか。長ければ分割する。
- 敬体と常体の混在が意図的か。
- 同じ語尾が続いていないか。
